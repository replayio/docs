Your coding agent (Claude Code, Cursor, Codex, …) can do everything you can do in the Replay QA web app. You do not need to learn the API yourself. Give your agent this prompt:

{/* Mirror of AGENT_PROMPT in replayio/loop-qa src/lib/docs.ts (pinned by scripts/check-agent-prompt.ts); keep identical. */}

```prompt
Use Replay QA to test and fix this app. Start at https://docs.replay.io/llms.txt and follow it.
```

[`llms.txt`](/llms.txt) is the entry point for agents. It links the Replay QA CLI workflow, the REST API (OpenAPI spec), the MCP server, the published agent skills, and these docs. Each of those describes itself, so the agent always reads the current version.

<Callout type="note" title="Which credential?">
  Your agent signs in with your Replay login, an `lqa_` Replay QA API token, or
  MCP OAuth sign-in, depending on how it connects. See [API keys and
  tokens](/reference/api-keys).
</Callout>

## The continuous QA loop

What the agent does with it:

1. **Create a project** for the running app, with a short note on the flows that matter most. Optionally include a design document describing what the app should do.
2. **Let QA run.** Replay QA drives exploration and testing itself; the agent waits until it finishes.
3. **Read the bugs.** Every [bug report](/reference/replay-qa/bug-reports) includes reproduction steps, expected versus actual behavior, a screenshot chronology, and a root-cause analysis traced through the Replay recording down to the responsible code. The agent does not need to debug; it reads the root cause and writes the fix.
4. **Mark each fix.** Replay QA reruns the affected journey to confirm it.
5. **Loop** until no open bugs remain.

If the bug report is not enough, the agent can open the linked recording with [Replay MCP](/basics/replay-mcp/overview) and inspect the failure directly.

## Connect an MCP client

Agents that prefer tools over HTTP calls can add the Replay QA MCP server. Most agents can run this setup themselves.

<Tabs labels={["Claude Code (sign-in)", "Claude Code (token)", "Cursor / VS Code", "Other"]}>

<Tab>

The server supports OAuth sign-in, so you can add it by URL without a token. Your client opens a browser sign-in the first time, and the connection then covers every project you have access to.

```sh
claude mcp add --transport http replay-qa https://qa.replay.io/api/mcp
```

</Tab>

<Tab>

```sh
claude mcp add replay-qa\
 --transport http https://qa.replay.io/api/mcp\
 --header "Authorization: Bearer lqa_your_token_here"
```

</Tab>

<Tab>

```json fileName=".cursor/mcp.json"
{
  "mcpServers": {
    "replay-qa": {
      "type": "streamable-http",
      "url": "https://qa.replay.io/api/mcp",
      "headers": {
        "Authorization": "Bearer lqa_your_token_here"
      }
    }
  }
}
```

VS Code uses the same shape under a top-level `servers` key in `.vscode/mcp.json`.

</Tab>

<Tab>

- **URL:** `https://qa.replay.io/api/mcp`
- **Transport:** HTTP (streamable)
- **Auth:** OAuth (discovery at `https://qa.replay.io/.well-known/oauth-protected-resource`) or `Authorization: Bearer lqa_...`

</Tab>

</Tabs>

The server lists its tools through MCP `tools/list`.

## Apps only reachable from your machine

For an app on `localhost` or a private network, the agent connects it through the Replay QA CLI's reverse proxy. [Testing a localhost app](/basics/replay-qa/localhost) explains the proxy. For CI builds, see [GitHub Actions](/basics/replay-qa/frpc-ci) or [CircleCI](/basics/replay-qa/circleci).
