---
title: How to record
---

Everything in Replay starts with a recording. A recording captures your application's runtime so you can inspect it after the fact — add console logs, inspect variables, step through code — without having to reproduce the bug again.

There are two ways to make a recording.

| Method                   | Best for                                     | How it works                                                     |
| ------------------------ | -------------------------------------------- | ---------------------------------------------------------------- |
| **Replay Browser + CLI** | Reproducing a bug by hand, or via your agent | Launches Replay Browser on a URL and uploads on close            |
| **Playwright**           | CI and automated test suites                 | The `@replayio/playwright` reporter runs tests in Replay Browser |

Both record at the browser runtime level, so the recording is an exact capture of what executed.

## Replay Browser + CLI

The Replay CLI installs the Replay Browser, launches it on a URL you choose, and uploads recordings to your Replay account.

<Steps>

## Install the Replay CLI

<Tabs labels={["npm", "yarn", "pnpm", "bun"]}>

<Tab>

```sh
npm i -g replayio
```

</Tab>

<Tab>

```sh
yarn add -g replayio
```

</Tab>

<Tab>

```sh
pnpm i -g replayio
```

</Tab>

<Tab>

```sh
bun i -g replayio
```

</Tab>

</Tabs>

## Record and upload

```sh
replayio record https://your-app.com
```

This opens the Replay Browser. Interact with your app to reproduce the issue, then close the browser. You'll be prompted to upload, and you'll get a URL to inspect the recording.

</Steps>

<Callout type="note">

**Agent-driven recording:** If you're working with an AI coding agent, it can trigger recordings for you using the `replay-cli` skill. Install it with `npx skills add https://github.com/replayio/skills --skill 'replay-cli'` and ask your agent to record your app.

</Callout>

## Playwright

For automated test suites, configure Playwright to run tests in Replay Browser and upload a recording of each test. When a test fails in CI you get a recording of what happened on that machine instead of having to reproduce it locally.

<Steps>

## Install the Replay Playwright plugin

```sh
npm i -D @replayio/playwright
npx replayio install
```

## Add the Replay browser to your Playwright config

```ts fileName="playwright.config.ts"
import { defineConfig } from '@playwright/test'
import { devices as replayDevices, replayReporter } from '@replayio/playwright'

export default defineConfig({
  reporter: [
    replayReporter({
      apiKey: process.env.REPLAY_API_KEY,
      upload: true,
    }),
    ['line'],
  ],
  projects: [
    {
      name: 'replay-chromium',
      use: { ...replayDevices['Replay Chromium'] },
    },
  ],
})
```

`REPLAY_API_KEY` is an [app.replay.io API key](/reference/api-keys). Each test run then uploads a recording per test, and the reporter prints the recording URLs.

</Steps>

<Callout type="note">

**Agent-driven setup:** AI coding agents can configure test recording for you using the `replay-playwright` skill. Install it with `npx skills add https://github.com/replayio/skills --skill 'replay-playwright'`.

</Callout>

## Chrome extension

The [Replay Debugger Chrome extension](https://chromewebstore.google.com/detail/replay-debugger/lkbmpddckbjbfaekcjacjgpehgaaijhh) records from inside your regular Chrome by capturing the page's inputs and re-executing your code against them. It is convenient when you cannot switch browsers, but the re-execution can differ from the original session in timing-sensitive code. Prefer the CLI when you can.

## FAQ

<Accordion>

<AccordionItem title="Which method should I use?">

- **Debugging a specific bug you can reproduce?** Use the **Replay Browser + CLI**, or ask your agent to do it with the `replay-cli` skill.
- **Debugging a failing Playwright test?** Set up **Playwright recording** so every run produces a recording you can inspect instead of re-running the test.
- **Working with an AI coding agent?** Any method works. Once the recording is uploaded, the agent can inspect it through Replay MCP regardless of how it was created.

</AccordionItem>

<AccordionItem title="How do I upload replays later?">

If you recorded with the Replay Browser CLI, you can upload later with `replayio upload`. See the [Replay CLI docs](/reference/replay-cli/commands).

</AccordionItem>

<AccordionItem title="Why do I need to log in?">

Recordings are uploaded to the Replay Cloud where the runtime can be replayed for time-travel debugging. See [How time travel works](/reference/time-travel/how-does-time-travel-work).

</AccordionItem>

<AccordionItem title="Can I record any website?">

Replay Browser can record any web application, including localhost, staging, and production URLs. For Playwright recording, the test project has to use the Replay Chromium device as shown above.

</AccordionItem>
